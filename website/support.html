Scaleway ControlRoom — Support

ControlRoom lists your Scaleway instances, starts and stops them, and shows what your organization costs this month. It talks only to Scaleway's API, with an API key you create.

Setting up an API key

Use a key that belongs to an IAM application made for ControlRoom, not your personal key. That way the app can do only what you allow, and you can revoke it at any time without touching anything else.

With the scw CLI

With the Scaleway CLI set up, these commands create the application, give it the permission sets below for all current and future projects (billing in a rule of its own, as Scaleway requires), and print the secret key and organization ID to paste into the app. The app shows the same commands with a Copy button under Add API key; with the same Apple account, copying on the iPhone and pasting in Terminal on a Mac just works. Leave out any permission set you do not want the app to have.

ORG=$(scw config get default-organization-id)
APP=$(scw iam application create name=controlroom description="ControlRoom iPhone app" -o template="{{ .ID }}")
scw iam policy create name=controlroom application-id=$APP \
  rules.0.organization-id=$ORG \
  rules.0.permission-set-names.0=InstancesFullAccess \
  rules.0.permission-set-names.1=AllProductsReadOnly \
  rules.1.organization-id=$ORG \
  rules.1.permission-set-names.0=BillingReadOnly &&
scw iam api-key create application-id=$APP description=controlroom &&
echo "Organization ID: $ORG"

In the console

  1. In the Scaleway console, open IAM → Applications and create an application, for example controlroom.
  2. Open IAM → Policies and create a policy for that application, with these permission sets:
    • InstancesFullAccess for the projects whose instances you want to start and stop. Use InstancesReadOnly to only look.
    • BillingReadOnly at organization level, to see costs.
    • AllProductsReadOnly, to list serverless apps and every other resource (databases, volumes, IPs, domains, secrets and the rest) and read their logs and metrics from Cockpit. Narrower sets work too: for example ContainersReadOnly, FunctionsReadOnly, ServerlessJobsReadOnly and ObservabilityReadOnly for serverless with its logs and metrics only. Listing secrets shows their names, never their values.
    Leave out what you do not want: the app hides what its key may not do.
  3. Open the application, choose API keys → Generate API key, and copy the secret key. It is shown only once.
  4. Copy your organization ID from Organization → Settings.
  5. In ControlRoom, tap Add API key, give it a name and paste both. Copying on a Mac and pasting on the iPhone works through the shared clipboard.

Repeat for each organization. When two keys can see the same instance, the app shows it once and uses whichever key is allowed to start or stop it.

Logs and metrics

Serverless containers and functions send their logs and metrics to Cockpit by themselves, jobs their logs. Open the app in the Serverless tab and tap Logs or Metrics. The app lists every metric Cockpit has for the app and charts the one you tap; counters are shown as a rate per second.

Instances do not. An agent on the instance has to push them to Cockpit; once it does, they show up in the app. The quickest way: open the instance in the app and tap Logs or Metrics. It shows three blocks of commands, filled in for that instance, each with a Copy button:

  1. on your computer, with the scw CLI: custom logs and metrics data sources in the instance's project and region, and a separate key that may push to them;
  2. on the instance: install Grafana Alloy;
  3. on the instance: write the Alloy configuration, with the two URLs and the key from step 1, and restart Alloy. It sends the system journal and basic system metrics (CPU, memory, load, disk, network) once a minute.

Or by hand in the console:

  1. In the console, open Cockpit → Data sources and create a custom data source of type Logs in the instance's region. Copy its URL.
  2. Create a separate API key that may push to Cockpit (an IAM application with ObservabilityFullAccess). Do not reuse the key in the app.
  3. Install Grafana Alloy on the instance.
  4. Copy the configuration from step 3 in the app: it writes /etc/alloy/config.alloy and restarts Alloy.

The configuration labels every line with the instance's ID (resource_id), which is how the app finds them. Logs you push yourself are billed by Scaleway as Cockpit custom data.

Frequently asked questions

Does stopping an instance stop all of its costs?
It stops the compute billing. Volumes and flexible IPs stay and are still billed.

Why do my costs differ from my invoice?
The figures come from Scaleway billing and exclude VAT. Scaleway updates them a few times a day, so the last hours may be missing. The invoice is the final word.

A key shows an error.
Scaleway rejected it: it may have expired, been deleted, or lack a permission. Check the policy of its application in the console. The other keys keep working.

How do I remove a key?
Tap it in Settings. That deletes it from your iPhone; to make it useless everywhere, also delete it in the Scaleway console.

Can I try the app without a Scaleway account?
Yes: tap Try the demo. It shows made-up instances and costs, and you can start and stop them.

Is this an official Scaleway app?
No. ControlRoom is an independent app. It is not made, endorsed or supported by Scaleway, so please send questions about the app to the address below, not to Scaleway.
